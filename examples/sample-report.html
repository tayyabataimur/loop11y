#1

23 elements have insufficient colour contrast

SERIOUS WCAG 1.4.3 23 elements

Why it matters: Users with low vision, colour blindness, or viewing in bright light cannot read this text. WCAG AA requires a 4.5:1 ratio for normal text and 3:1 for large text.

How to fix: Increase the contrast between text and background colour. Common fixes: darken text colour, lighten background, or increase font weight.

Example fix
Before
color: #9CA3AF; /* 2.85:1 on white — fails */
After
color: #6B7280; /* 4.62:1 on white — passes AA */

#2

12 images are missing alternative text

CRITICAL WCAG 1.1.1 12 elements Auto-fixable

Why it matters: Screen reader users hear nothing or the filename. The content is completely lost for users who can't see images.

How to fix: Add an alt attribute to every img. Use descriptive text. For decorative images, use alt="".

Example fix
Before
<img src="hero-banner.jpg">
After
<img src="hero-banner.jpg" alt="Two designers reviewing wireframes on a laptop">

#3

5 buttons have no accessible name

CRITICAL WCAG 4.1.2 5 elements Auto-fixable

Why it matters: Screen reader users hear 'button' with no indication of what it does. Keyboard and voice control users cannot target by name.

How to fix: Add aria-label to icon-only buttons. Ensure visible text describes the action.

Example fix
Before
<button><svg aria-hidden="true">…</svg></button>
After
<button aria-label="Add to cart"><svg aria-hidden="true">…</svg></button>

#4

4 form fields are missing a label

SERIOUS WCAG 1.3.1 4.1.2 4 elements

Why it matters: Screen reader users cannot identify what information a field expects. Voice control users cannot target by name.

How to fix: Associate a label element with every input via for/htmlFor. Placeholders are not labels.

Example fix
Before
<input type="email" placeholder="Email address">
After
<label for="email">Email</label><input id="email" type="email">
